# Configurator surface brief

## Surface and mode

Target: addons/cs_prefab_configurator/static/index.html, route /prefab.
Mode: Operate.
Build path: code-led, implementing the approved four-stage architectural product-tool direction. The shared procedural 3D scene is the principal visual asset; no generated design comp or competitor render is used.

## Direction contract

A digital architectural workbench. The first viewport demonstrates a building whose dimensions and options can be edited immediately. On desktop, the scene fills the larger left column; a compact white panel on the right carries navigation, grouped choices and a stable price/next footer. On mobile, a compact scene stays above the independently scrollable choices and fixed action area.

White and warm stone surfaces, dark ink, restrained green selection/action color. One locally hosted DM Sans family. Precise dividing lines separate work areas; rounded option controls do not become a page of decorative cards. The supplied Prefab Partner logo is retained without altering its drawing.

## Interaction

- Four navigable stages retain all product choices using accordion subgroups.
- Dimensions are visible immediately; material families group the facade choices.
- Interior ceiling and wall positions use checkboxes in physically meaningful row/column arrangements.
- Choosing an interior stage opens an interior camera; camera controls allow cutaway and ceiling inspection.
- Example device visibility stays out of saved commercial state. Server resolved scope drives textual status and renderer representation.
- Dependent fields disappear when inapplicable. The server's canonical response is adopted with a short explanation when positions must be cleared.
- A changed catalogue revision is presented as a recoverable review state.
- Save design, share link and create personal proposal remain distinct actions.

## Quality floor

At 390 by 844, the model, width/depth input and next button must be visible initially. All four steps and dialogs must work using keyboard and pointer. The 2D fallback remains usable if WebGL cannot start. Controls have visible focus, native input semantics and text descriptions; scope is never color-only.

## Visual truth and limits

Parametric scenes, plans and scope must refer to the same selection. The setup is not a production drawing. Contours identify representative devices that are not included; included indicative models retain an explicit model qualifier. No competitor images or invented commercial claims ship.

## Verification

Model/state regressions cover canonical typed selections, legacy migration, dependent resets and view-state exclusion. Browser paths cover four-step editing, persistence/sharing, scope visibility, quote/PDF, out-of-order pricing, offline recovery and viewport behavior. Current evidence is written by verification scripts under docs/verification.
